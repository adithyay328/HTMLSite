On one hand, we have to do organization of the source files and deployment files. But, we also have to organize the site itself.

As of now, we only have 1 page: the home page, containing some details about me. It's a good start, and still will be the homepage for the site. But, what content pages do we need?

Let's keep it simple for now:
- 2 types of posts: Long and Short. Name is self-explanatory
- Later, could add Longer, surveys, whatever
- Short is to the point, no exposition, quicker write ups
- Long is for more holistic write ups 

Later, we can re-structure this. For now, this is good enough. All core nav is still on the homepage, to keep the page lightweight.

One important note: I don't even think it matters long term how the website is organized, as long as all pages are a) in the sitemap and b) have some link the user can get to, somehow.

The reason for this is that in practice, most if not all traffic is going to come from people googling for topics I cover. No one is going to go "ahh yes, lemme go to Adi's site and navigate". Rather, they'll google "how do I solve SVD LLS for homogenous LLS", and they'll find my page as an option. So really, design good content, and a functional if not pretty nav layout, and search engines will do the rest of the work.

Honestly, How To for short + Posts for long is probably sufficient. Simple.

Keep 2 panes in the main page containing the 5 most recent posts for each catgory, and then a link below to a massive list of every post of that category. It allows basic visiblity for humans in case they're curious, but still is search engine indexable.
